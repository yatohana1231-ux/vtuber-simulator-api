# 評価基準: absenceSimulator

absenceSimulator の出力は、不在期間中にキャラクターが過ごした出来事（events）と行動（actions）。サーバーが決めた骨格（行動の枠・出来事の種類・続いている話題）に、LLM が内容を書き足す。採点時には、シナリオの説明・`judgeFocus`・骨格（行動の枠・出来事の種類・続いている話題・最近の出来事）・出力（events/actions/threadUpdates/newThreads）に加えて、キャラクターの性格・設定と世界観（パッケージ）を渡す。件数・枠番号の一致などルールで判定できる形式面は `checks` で見るため、ここでは内容の質だけを見る。

### settingConsistency: 世界観・キャラクターとの整合

出来事・行動の内容が、世界観のルール・キャラクターの性格や設定と矛盾していないか。

- 5: すべての出来事・行動が世界観・キャラクター設定に沿っており、違和感が無い
- 3: おおむね沿っているが、設定からやや外れた表現が1箇所ある
- 1: 世界観のルールに反する要素や、キャラクター設定と明らかに矛盾する内容がある

### actionSlotFit: 行動と時間帯の整合

各行動の枠の過ごし方（activity）に対して、その枠の action・memo や、その時間帯に起きたとされる出来事が、時間帯らしい内容になっているか（就寝中に出かける・食べるなど、枠の過ごし方とかけ離れた内容になっていないか）。

- 5: すべての枠・出来事が、その時間帯の過ごし方として自然
- 3: 一部の枠でやや時間帯にそぐわない内容があるが、大きな矛盾ではない
- 1: 就寝中に活動する、枠に無い予定を勝手に足すなど、時間帯と明らかに矛盾する内容がある

### eventQuality: 出来事の具体性と面白さ

出来事の summary・detail が、プレイヤーに聞かれたときに話せる具体的な内容になっており、会話のネタとして面白みがあるか。

- 5: どの出来事も具体的で、キャラクターらしいディテールがあり、話しかけたくなる内容
- 3: 具体性はあるが、ありきたりで面白みに欠ける出来事が混じっている
- 1: 抽象的・紋切り型で、detail が summary の言い換えに留まっている出来事が多い

### threadHandling: 続いている話題の扱い

続いている話題の続き・閉じ方・新しい話題の始め方が自然か。関係の無い出来事に話題を紐付けていないか、進展の無い話題を無理に閉じていないか、既存の話題と似た新しい話題を重ねていないか。

- 5: 続きの出来事・クローズ・新しい話題のいずれも自然で、重複や無理なクローズが無い
- 3: おおむね自然だが、やや強引な紐付けやクローズが1件ある
- 1: 無関係な出来事に話題を紐付ける、進展なく閉じる、既存の話題とほぼ同じ話題を新しく作るなどが目立つ

### variety: 多様さ

複数の出来事がある場合に内容が偏らず、また直近の記録の出来事と似た内容を繰り返していないか。

- 5: 出来事どうし・直近の記録との重複が無く、種類（日常・ちょっと嬉しい・トラブル・発見）に沿った多様な内容
- 3: 一部似た切り口の出来事があるが、明らかな繰り返しではない
- 1: 直近の記録とほぼ同じ出来事を繰り返す、または複数の出来事が似た内容に偏っている
