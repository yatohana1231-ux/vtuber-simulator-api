# rubrics

LLM による採点（AI 応答テストのフェーズ5で使う）の評価基準。機能ごとに1ファイル（`<機能名>.md`）。採点用のモデルは、シナリオの説明・`judgeFocus`・入力・出力と、この評価基準を読み、観点ごとに 1〜5 で採点して理由を書く。

## 書式（仕組みが機械的に読むので守ること）

```markdown
# 評価基準: <機能名>

<この機能の出力が何か、採点するときの前提（人が読む説明）>

### <観点の id（英数字のキャメルケース）>: <観点の名前>

<何を見るか（1〜2文）>

- 5: <満点の状態>
- 3: <中間の状態>
- 1: <最低の状態>
```

- 観点は `### id: 名前` の見出しで始め、その下に説明と、`- 5:`・`- 3:`・`- 1:` の3行を必ず置く（2と4はその間）。
- 観点の数は1ファイル3〜6個。ルールで判定できること（文字数・JSON の形など）は観点にしない（`checks` で見る）。
- 特定の世界観・キャラクターに依存する文面は書かない（「キャラクターの設定に合っているか」のように書き、具体的な設定は採点時にパッケージから渡す）。
- 観点を変えたら、基準（`../baseline/`）を取り直す（変える前後の点数は比べられない）。
