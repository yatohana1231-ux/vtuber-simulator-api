# lifestyles

生活様式のデータファイル。平日・休日の生活リズム（時間帯ごとの大まかな過ごし方）と、不在期間に起こりやすい出来事の種類を持つ。`packages/` から `"lifestyle": "<key>"` で参照する（生活リズムや起こりやすい出来事は、世界観とキャラクターの組み合わせで決まるため、世界観・キャラクター単体ではなくパッケージに紐付けている）。

現時点（フェーズ1）ではまだどのコードからも参照されない。フェーズ2以降の不在期間のシミュレーション（`src/absenceSimulator/`、詳細は `.notes/done/absence-simulation-roadmap.md`）が、ここから行動の枠と出来事の抽選に使う予定。

## ファイル一覧

| ファイル | 内容 |
|---|---|
| `tokyo-highschool-vtuber.json` | 東京都内の高校2年生・最近VTuberデビューした生活様式（`yui-modern-tokyo` パッケージ用） |

## フィールド

| フィールド | 型 | 説明 |
|---|---|---|
| `key` | string | 識別子。ファイル名（拡張子なし）と同じ値 |
| `schedules.weekday` | ScheduleSlot[] | 平日の生活リズム |
| `schedules.holiday` | ScheduleSlot[] | 休日（土日）の生活リズム。祝日は扱わない |
| `eventKinds` | EventKind[] | 起こりやすい出来事の種類（1件以上） |

`ScheduleSlot` の形式:

| フィールド | 型 | 説明 |
|---|---|---|
| `start` | string | 枠の開始時刻。`"HH:MM"` |
| `end` | string | 枠の終了時刻。`"HH:MM"` |
| `activity` | string | 大まかな過ごし方。具体的すぎない文面にし、肉付け（何を、どんな内容で、といった具体化）は LLM に任せる |
| `fatigueChangePerHour` | number（省略可。−100〜+100） | この枠で1時間あたりに疲労が増える量（負なら回復）。省略時は 0。疲労（0〜100）は保存した値を使わず、直近48時間ぶんの枠を積み上げて毎回計算する（D-040、`src/lib/affect/needs.ts`）。1日の合計がほぼ 0 になる（起きている間にたまり、寝て回復する）ように決める。同じ `activity` の文字列には、平日・休日とも同じ値を付ける |

`EventKind` の形式:

| フィールド | 型 | 説明 |
|---|---|---|
| `key` | string | 識別子 |
| `label` | string | 表示・プロンプト用のラベル（例: 「日常のひとコマ」） |
| `weight` | number | 正の数。抽選時の重み（大きいほど選ばれやすい） |

## 注意

- 時刻は世界観（`worlds/*.json` の `timezone`）のタイムゾーンでの時刻として扱う。
- `end` が `start` 以下の枠は、日をまたぐ枠として扱う（例: `{"start":"23:00","end":"07:00"}` は当日23:00から翌日7:00まで）。
- 枠どうしが重ならないようにする。枠と枠の間に空きがあってもよい（その時間の行動は生成しない）。
- 枠どうしの重なりのチェックは `src/lib/packages.ts` の読み込み時にはまだ行っていない（フェーズ2の骨格生成で扱う予定）。
- 日をまたぐ枠は、翌日の曜日の種類が違うと翌日の枠と重なったり間が空いたりする（例: 日曜〔休日〕の就寝 `23:00`→`08:00` と、月曜〔平日〕の起床 `07:00`〜）。この扱いはフェーズ2の骨格生成で決める。
- 文面は具体的すぎず、大まかな過ごし方にとどめる。LLM が不在期間のシミュレーションで内容を肉付けする前提。
